1. INTRODUCTION
1.1 Features
      The UART provides:
 Compliance to the AMBA Specification (Rev 2.0) onwards for easy integration into SoC implementation.
 Separate 32x8 transmit and 32x12 receive First-In, First-Out (FIFO) memory buffers to reduce CPU interrupts
 Programmable FIFO disabling for 1-byte depth.
 Supports start, stop, and parity bits for asynchronous communication.
 Independent masking of transmit FIFO, receive FIFO, and receive timeout and error condition interrupts.

2.2 Functional Description
      2.2.1AMBA APB Interface
      The AMBA APB interface generates read and write decodes for accesses to status/control registers, and transmit and receive FIFOs.
 RESET
         The UART are reset by the global reset signal PRESETn and a block-specific reset signal UARTRST. 
         In order to avoid serious operational failures, both clock domains of the APB_UART must be reset before any attempt is made to send or receive data on the serial line; that is, it is an illegal operation to reset just one clock domain of the APB_UART without resetting the other clock domain.Each reset signal must be de-asserted synchronously with the corresponding clock signal
 Clock signals
         The UART uses primary clock signal, PCLK is Peripheral Clock, and this clock drives the APB interface for read and write operations to the UART registers. It is used by the system to access control, status, data registers through the APB bus.
     
      UARTCLK is UART Functional Clock, used internally by the UART for baud rate generation and data transmission/reception. The selected frequency for UARTCLK must support the required baud rate. UARTCLK is sourced from the same clock as PCLK.
     
      2.2.2 Register block
                        The register block stores data written, or to be read across the AMBA APB interface.
      2.2.3 Baud rate generator
         The baud rate generator contains free-running counters that generate the internal x16 clocks, Baud16. Baud16 provides timing information for UART transmit and receive control. Baud16 is a stream of pulses with a width of one UARTCLK clock period and a frequency of 16 times the baud rate. 
 Baud rate calculation
         The baud rate divisor is a 22-bit number consisting of a 16-bit integer and a 6-bit fractional part. This is used by the baud rate generator to determine the bit period. The fractional baud rate divider enables the use of any clock with a frequency >3.6864MHz to act as UARTCLK, while it is still possible to generate all the standard baud rates.
      The Baud Rate Divisor has the following relationship to UARTCLK:
 Baud Rate Divisor = UARTCLK/(16xBaud Rate) = BRDI + BRDF
         
            Example of how to calculate the divisor value:
            If the required baud rate is 115200 and UARTCLK = 100 MHz then:
      Baud Rate Divisor = (100x10^6) / (16x 115200) = 54.25347
      This means BRDI = 54 and BRDF = 0.25347.
      Therefore, fractional part, m = integer ((0.25347x64) +0.5) = 16
      Generated baud rate divider = 54 + 16/64 = 54.25
      
      Generated baud rate = (100x10^6) / (16x54.25) = 115207
      Error = (115207−115200)/ 115200 x 100 = 0.006%
      The maximum error using a 6-bit UARTFBRD Register = 1/64x100 = 1.56%. This occurs when m = 1, and the error is cumulative over 64 clock ticks

      2.2.4 TX FIFO
      The transmit FIFO is an 8-bit wide, 32 location deep, FIFO memory buffer. CPU data written across the APB interface is stored in the FIFO until read out by the transmit logic. You can disable the transmit FIFO to act like a one-byte holding register.
      2.2.5 RX FIFO
      The receive FIFO is a 12-bit wide, 32 location deep, FIFO memory buffer. Received data and corresponding error bits, are stored in the receive FIFO by the receive logic until read out by the CPU across the APB interface. The receive FIFO can be disabled to act like a one-byte holding register.
 Error bits 
      Three error bits are stored in bits [10:8] of the receive FIFO, and are associated with a particular character. There is an additional error that indicates an overrun error and this is stored in bit 11 of the receive FIFO.
      The overrun bit is not associated with the character in the receive FIFO. The overrun error is set when the FIFO is full, and the next character is completely received in the shift register. The data in the shift register is overwritten, but it is not written into the FIFO. When an empty location is available in the receive FIFO, and another character is received, the state of the overrun bit is copied into the receive FIFO along with the received character. The overrun state is then cleared. Table lists the bit functions of the receive FIFO

      2.2.6 Transmit logic
      The transmit logic performs parallel-to-serial conversion on the data read from the transmit FIFO. Control logic outputs the serial bit stream beginning with a start bit, data bits with the Least Significant Bit (LSB) first, followed by the parity bit, and then the stop bits according to the programmed configuration in control registers.
      2.2.7 Receive logic
      The receive logic performs serial-to-parallel conversion on the received bit stream after a valid start pulse has been detected. Overrun, parity, frame error checking, and line break detection are also performed, and their status accompanies the data that is written to the receive FIFO.

      3.1 UARTDR 
      The Data Register (UARTDR) is used to hold data that is transmitted or received through the UART interface. It allows reading the received data and writing the data to be transmitted. 
      For words to be transmitted:
 If the FIFOs are enabled, data written to this location is pushed onto the transmit FIFO.
 If the FIFOs are not enabled, data is stored in the transmitter holding register (the bottom word of the transmit FIFO).
      For received words: 
 If the FIFOs are enabled, the data byte and the 4-bit status (break, frame, parity, and overrun) is pushed onto the 12-bit wide receiver FIFO.
 If the FIFOs are not enabled, the data byte and status are stored in the receiving holding register (the bottom word of the receive FIFO).

4. OPERATION
      The operation of the UART is described in the following sections:
      Control data is written to the UART Line Control Register, UARTLCR_H. This register is 30-bits wide internally, but is externally accessed through the APB interface by writes to the following registers:
      UARTCR: Control Register  --  enables UART and flow control.
      UARTLCR_H: set the
                transmission parameters
                word length
                buffer mode
                number of transmitted stop bits
                parity mode
                Break generation.
      UARTIBRD: Defines the integer baud rate divider 
      UARTFBRD: Defines the fractional baud rate divider
      4.1 Data transmission
      Data received or transmitted is stored in two 32-byte FIFOs, though the receive FIFO has an extra four bits per character for status information.
      For transmission, data is written into the transmit FIFO. If the UART is enabled, it causes a data frame to start transmitting with the parameters indicated in the Line Control Register. Data continues to be transmitted until there is no data left in the transmit FIFO. The BUSY signal goes HIGH as soon as data is written to the transmit FIFO (that is, the FIFO is non-empty) and remains asserted HIGH while data is being transmitted. BUSY is negated only when the transmit FIFO is empty, and the last character has been transmitted from the shift register, including the stop bits. BUSY can be asserted HIGH even though the UART might no longer be enabled.
      4.2 Data reception 
      When the receiver is idle (UARTRXD continuously 1, in the marking state) and a LOW is detected on the data input (a start bit has been received), the receive counter, with the clock enabled by Baud16, begins running and data is sampled on the eighth cycle of that counter in UART mode.
      The start bit is valid if UARTRXD is still LOW on the eighth cycle of Baud16, otherwise a false start bit is detected and it is ignored.
      If the start bit was valid, successive data bits are sampled on every 16th cycle of Baud16 (that is, one bit period later) according to the programmed length of the data characters. The parity bit is then checked if parity mode was enabled.
            
      4.3 Loopback 
      You can perform loopback testing for UART data by setting the Loop Back Enable (LBE) bit to 1 in the Control Register. Data transmitted on UARTTXD is received on the UARTRXD input.
